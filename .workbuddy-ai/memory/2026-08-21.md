## legal/ folder study (v1.23 of the standard)
- User directed study of `legal/` (12 files, **92 KB**) — a **legal/compliance/consent Python package** (not just docs): `manager.py` (`LegalManager` master coordinator), `cli.py` (`legal_ctl` argparse CLI), `disclaimer.py` (`DisclaimerRegistry`/`RiskLevel` — clean), `consent.py` (`ConsentManager` + cryptographic consent ledger), `contributors.py` (`ContributorRegistry` + DCO), `donations.py` (`DonationsManager` — hardcoded creator IBANs/phones/emails + sponsor tiers), `licenses.py` (`LicenseManager` — multi-license scanner), `maintainers.py` (`MaintainerRegistry` — PQC/PGP fingerprints), `safety_check.py` (`SafetyChecker` — pre-exec backup), `test_legal.py` (8-test suite), `README.md`, `__init__.py`.
- **Injection-safe at Python level:** no `subprocess`/`shell=True`/`eval`/`exec`/`pickle`/`ctypes`/`os.system`/`yaml.load` anywhere (good). 10/12 `.py` have `from __future__` + `logging` + type hints + docstrings — **the strongest baseline discipline of any folder studied** (better than `dev/`'s GPLv3 model). But it is the **single largest Apache-2.0 cluster** (all 11 `.py` headers + `licenses.py` docstring say "Licence: Apache 2.0"; `README.md:40` defines the project license set as Apache-2.0/GPL-2.0/MIT with **no GPL-3.0**).
- **🔴 H128 (H7 lives here):** `legal/licenses.py` docstring (L8-13) + `get_license_text` default (L72-73) codify **Apache-2.0 as the primary/canonical license**, directly contradicting the adopted **H7 → GPL-3.0 canonical** decision. `_LICENSE_TEXTS` has **no GPL-3.0 entry** and `scan_directory` only maps `"GPL"` → `GPL-2.0` (never detects GPL-3.0). This folder is where H7 must be resolved decisively.
- **🔴 H129:** `scan_directory` is a **fail-open license compliance audit** — a file is "compliant" if it contains "Apache"/"GPL"/"MIT"/"Licence"/"License"/"Copyright" (L100-115); a file merely mentioning "Copyright" is classified "Custom/Proprietary" and counted compliant. So proprietary/unknown licenses pass; `is_fully_compliant` only fails on files with zero license-ish words. The audit cannot enforce the GPL-3.0 mandate.
- **🔴 H130:** `get_license_text(name)` **silently returns Apache-2.0 text for any unknown name, incl. "GPL-3.0"** (L72-73) — no GPL-3.0 entry exists, so callers requesting the canonical license text get the wrong license (correctness/integrity bug in attribution).
- **🔴 H131:** `consent.require_consent_interactive` **fails OPEN** — auto-grants in `dry_run` (L173-175) and, in any non-interactive (non-TTY) env, calls `grant_consent("I AGREE")` with no user input (L187-189). The mandatory "I AGREE" legal gate is bypassed in automation (same family as H29/H99; contrast `installer.py` which fails CLOSED).
- **🔴 H135:** `cli.py` `consent` subcommand **hardcodes `user_response="I AGREE"`** (L101-105) → `python -m legal.cli consent` auto-grants consent with no user action; `test_legal.py:229` encodes this as expected. The provided tool bypasses the gate.
- **🟡 H132:** the "cryptographic" consent token (L131-132) is `sha256` of *public* values with no key/HMAC/asymmetric sig — forgeable, and `load_ledger` (L77-89) doesn't verify integrity, so the audit ledger is tamperable (overstated-claim family, cf. H51/H111).
- **🟡 H133:** `consent.DEFAULT_LEDGER_PATH` is a hardcoded dev Windows path `F:/Pension Person Details/UmerOS/var/lib/umeros/consent_ledger.json` (L35) — breaks on other machines/OSes (cf. H43). **🟡 H134:** consent recorded under default "admin" with no identity check; PII (name/host/machine_id/timestamp) stored unencrypted in JSON ledger (§4.3).
- **🟡 H136:** `contributors.verify_dco` is decorative — `dco_signed` defaults `True` (L37/L89), `add_contributor` never verifies a real DCO/CLA signature; the "verification engine" returns a pre-set boolean (cf. H51/H111/H132). **🟡 H138:** `maintainers` PQC/PGP fingerprints are **hardcoded static literals** (L44-45), not derived from real keys — forgeable "cryptographic identity"; `cli.py` prints them as real "PQC Key"/"PGP Key".
- **🟡 H139:** `safety_check.verify_safety` defaults `is_safe=True` (L66) and only blocks on <500 MB free or a *CRITICAL*-level backup failure (L103-104); a failed backup on HIGH/MODERATE ops (disk partition, kernel module) yields only a warning while still "safe" — soft/fail-open safety gate (same family as H29/H99/H131).
- **🟡/🔴 H140:** `test_legal.py` Test 4 asserts `verify_dco("Antigravity AI / DeepMind Team")` is `True` (L120-121), but that name is **NOT in the roster** → `verify_dco` returns `False` and the test *fails as written*. No CI step exists to catch it (cf. H16). **🟡 H141:** tests encode the fail-open `consent` CLI as expected (L229) and don't cover `require_consent_interactive`'s non-TTY auto-grant, license-audit accuracy (H129/H130), or safety-blocking (H139).
- **💭 H137:** real personal PII/financial data hardcoded in source — `mumeryasin123456789@gmail.com` in `contributors.py:49` + `maintainers.py:42`; full IBANs/phones/emails/Wise/Payoneer in `donations.py:49-143`. Intentional (donation appeal) but sensitive; should be configurable/outside source control. **💭 H142:** `DonationTier` labels mismatch code thresholds (SILVER "$50+" vs `>=500`). **💭 H143:** `ContributorRole(str)` should be `Enum`; disclaimer text L86 "DEEPMIND AI ASSISTANTS" copy-paste artifact. **💭 H144:** `licenses.py` reads 2 KB + `errors="ignore"`; `sys.path` import hack; **0/12 `legal/` files carry a tier label**; `README.md:131` references `tests/test_legal.py` (not in `tests/`). **💭 H145:** relative imports rely on `sys.path.insert` instead of `from .consent import ...`.
- **Positives:** `disclaimer.py`/`manager.py`/`safety_check.py` are clean, well-structured models; `safety_check` actually creates `shutil.copy2`/`copytree` checkpoints (bounded, `Path.resolve()`); no injection surface anywhere; the `consent` ledger persists + revokes correctly on the happy path (only the gate's automation bypass is broken).

## lib/ folder study (v1.24 of the standard)
- User directed study of `lib/` (33 source modules — 25 top-level `.py` + 8 in `lostfound/`) — a **faithful FHS `/lib` simulation**: shared-library / ELF / dynamic-linker / kernel-module / filesystem-layout modeling. Read in full: `security.py`, `ssl_libs.py`, `kernel_modules.py` (30 KB), `dynamic_linker.py` (24 KB), `fhs.py`, `var_lib.py`, `lostfound/fsck.py`, `lostfound/__init__.py`, `lib/__init__.py`, `lib/README.md`; grepped all 33 for dangerous calls (`subprocess`/`eval`/`exec`/`pickle`/`ctypes`/`shell=True`/`marshal`/`shelve`/`yaml.load`) = **none**; for fail-open/verify patterns = only `ssl_libs.py`.
- **Best-disciplined folder in the entire study.** Every module has `from __future__ import annotations` + `logging.getLogger` + type hints + Google docstrings + a `_selftest()`; consistent enums/dataclasses; 21 modules documented in `lib/README.md` TLDP coverage map. `dynamic_linker.py` faithfully models the glibc `ld.so.cache` binary format (magic + header + entry structs) and parses it with correct bounds (string-table offset) — safe. `kernel_modules.py` is a clean `depmod`/`modprobe`/`rmmod` simulation with acyclic dependency resolution + safe MD5 integrity fingerprinting. `lostfound/fsck.py` is a **model fail-closed** checker: marks the FS clean only when `superblock_ok and unresolved_orphans == 0 and errors_found == errors_fixed`; corrupted inodes are flagged unrecoverable (not silently passed). `fhs.py` audit is conservative (`ok` only when no ERROR issues). `var_lib.py` is pure metadata (documents `/var/lib` state — no secret handling).
- **🔴 H3 re-confirmed:** `lib/security.py:72` `PASSWORD = "password"` is a hardcoded module-level constant in the PAM catalogue. Latent — it is **not referenced in any active auth path** (catalog metadata only), so blast radius is low, but it is a hardcoded-weak-credential smell and must be removed/replaced (matches the known H3).
- **🔴 H146 (NEW, trust/verify fail-open):** `lib/ssl_libs.py` — `_check_is_trusted` (L414-427) returns `True` whenever ANY `ca-certificates.crt` file exists on disk ("If store exists, assume basic trust", L424); `check_trust` (L225-245) treats any `is_ca` cert as trusted and only string-matches `issuer==subject` — **no cryptographic signature validation**. So any cert in a store with a CA bundle file is reported "trusted". Same family as H17/H111/H128/H129. `_check_is_trusted` also returns `True` when `store_paths` has a dir with a bundle file, regardless of the cert — pure presence-based trust.
- **🔴 H147 (NEW, expiry fail-open):** `ssl_libs.py` `CertInfo.is_expired` (L83-87) unconditionally returns `False` ("simplified: returns False if parsing fails"), and `days_until_expiry` (L92) returns a hardcoded `365`. So expired certificates never appear expired — expiry enforcement is decorative (same family as H111 dummy-crypto). `not_after`/`not_before` are never even parsed from the cert.
- **💭 H148 (NEW):** `ssl_libs.py` whole module is a "simplified" string-parsed simulation — no `cryptography`/OpenSSL use; `is_ca` heuristic is loose ("CA:TRUE" substring in text); `key_size`/`signature_algorithm` are hardcoded defaults (2048 / SHA256withRSA); fingerprints via `hashlib` are correct but trust + expiry are not enforced. It ships as if production-ready but should carry an `[EXPERIMENTAL]`/`[FUTURE]` tier label.
- **🟡 H149 (NEW, H7 family):** `lib/` is the **largest Apache-2.0 cluster** — ~23 `lib/` files carry `Licence: Apache 2.0` headers (`security.py`/`ssl_libs.py`/`kernel_modules.py`/`dynamic_linker.py`/`arch.py`/`firmware.py`/`__main__.py`/`kbd.py`/`__init__.py`/`essential_libs.py`/`iptables_libs.py`/`ldd.py`/`iconv.py`/`libinfo.py`/`library_manager.py`/`var_lib.py`/`oss.py`/`usr_include.py`/`multiarch.py`/`tmpfiles.py`/`usr_lib.py`/`elf_parser.py`/`lostfound/__init__.py`) and `lib/README.md:138` asserts "Apache 2.0 - same as the rest of Umer OS" — directly contradicts the adopted **H7 → GPL-3.0 canonical** decision. This is the single biggest concentration of Apache strays in the repo (joins `ai/`/`boot/`/`etc/`/`feedback/`/`fs/`/`initrd/`/`legal/`).
- **💭 H150 (NEW):** `lib/security.py` registers `pam_permit.so` ("Always permit") as a stock PAM module (L116-118) — realistic FHS, but if the `security/` subsystem ever consults this registry for auth decisions a default could fail-open (metadata only, low risk; worth a note that `pam_permit` must never be auto-selected).
- **Positives / models to copy:** clean binary `ld.so.cache` parser (`dynamic_linker.py`), fail-closed `fsck` (`lostfound/fsck.py`), conservative FHS audit (`fhs.py`), full per-file baseline across 33 modules, zero dangerous calls, zero injection surface. This folder is the baseline-discipline exemplar for the rest of the repo.
- **Fix order (lib/):** fail-closed `_check_is_trusted` (verify signatures vs an actual trust store) + real expiry (`not_after` vs now) → resolve H7 (relicense ~23 modules to GPL-3.0) → remove H3 constant + add H150 caveat.
