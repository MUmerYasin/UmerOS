### H17 — `security/security.py` `SecureBoot.verify_image` / `verify_bytes` (fail-open → fail-closed)
- Root cause: when an image had **no trust-store entry AND no caller-supplied `expected_hash`**
  (`stored is None`), the default `strict_mode=False` branch returned `True` — unknown
  components were silently allowed to boot/load.
- Fix:
  - Flipped the default to `strict_mode=True` (fail-closed by default).
  - In the `stored is None` branch, both strict and dev modes now **deny**: strict raises
    `PermissionError`; dev mode logs + returns `False` (never `True`).
  - Applied to both `verify_image` and `verify_bytes`. Caller-supplied `expected_hash` still
    verifies against that hash (not fail-open).

### H51 — `compatibility/container.py` `ZeroTrustContainer.execute_binary` (fail-open → fail-closed)
- Root cause: `self.capabilities.check(self.container_id, "HARDWARE")` result was only used to
  *print* a message; the binary then ran **unconditionally** and the "hardware restriction" was
  purely cosmetic. (`CapabilityManager.check` actually *raises* on denial, but the check never
  gated execution — fail-open.)
- Fix:
  - Added `import logging` + module logger `log`.
  - Execution is now DENIED unless the container holds the capability: switched to the
    non-raising `self.capabilities.query(container_id, "HARDWARE")`; on `False` it logs a denial
    and `return False` (graceful fail-closed) without running the binary. On `True` it proceeds
    and performs the hardware syscalls (capability granted).

### H37 — `bin/user_commands.py` `LoginCommand.execute` (silent auth bypass -> fail-closed)  [CODE FIX]
- Root cause: `_parse_args` accepted `-f <user>` and `-F` (force) and set `opts["skip_auth"]=True`;

  zero-trust violation). The `crypt.crypt` password verification was never reached.
- Fix:
  - `LoginCommand.execute` now DENIES any `skip_auth` request immediately (`print("Login incorrect");

    Authentication is fail-closed — there is no code path that skips it.
  - The `-f`/`-F` flags are still parsed (CLI compat) and recorded as `skip_auth=True`, but they now
    lead to a denial rather than a silent login. Docstring updated to mark them removed/denied (H37).
  - Both changes carry `# [FIX H37]` traceability comments.
