## Session 188 — H188 (`opt/` shell injection in generated PATH/profile snippets)
- Closed the one real exploit in the `opt/` sweep: `bin_path` was interpolated unescaped
  into `export PATH="<path>:$PATH"` in `/etc/profile.d/opt-paths.sh` and in a block
  appended to `~/.bashrc` — both login-sourced, so a package dir name containing `"`
  ran arbitrary commands for every user. `MANPATH`/`LD_LIBRARY_PATH` had it too.
- Two guards: `_drop_shell_unsafe()` (drop + log hostile names below the root) and
  `_shell_export()` (`shlex.quote` per path, `export VAR=<q>:…:$VAR`).
- `~/.bashrc` mutation now needs explicit consent (`allow_home_profile` / explicit
  `profile_path=`), otherwise `PermissionError`.
- Bonus fixes: two `export OPT_ROOT/OPT_PATH` lines were missing their `f` prefix (emitted
  the literal `{self.opt_root}`); `OptPathManager._discover_packages()` had a dead `else`
  so the flat `/opt/<pkg>/bin` layout was never discovered; six `print()` error paths
  became logging under a new module logger.
- Windows lesson: `Path.parts` includes the drive, so name validation must be scoped below
  the root (caught by `opt/env.py`'s own selftest).
- New `tests/test_opt_shell_h188.py` 17 passed (incl. a real bash injection attempt).
- Full run 4190 `<testcase>` nodes / 6 failed / 0 errors / 64 skipped — the same six
