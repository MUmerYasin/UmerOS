## Standing working conventions (Code Review Expert / Kim)

- **Review-standard-first workflow:** After *every* study of the codebase (any file, folder, design source, or dependency), update
  `MainTask/Raw Data/Code Review Standards and Process.md`. This is a standing user instruction — do not treat studies as read-only.
  - Bump the version in the header (v1.1 → v1.2 → v1.3 …) and note what changed.
  - Fold real findings into: the §1 facts table, §4 checklist, §7 CI, the §9 hotspot table (H1…Hn), and §11 quick reference.
  - Study sources so far: `main.py`, `setup.py`, `docs/developer_guide.md`, `.github/workflows/security_scan.yml`,
    `MainTask/codex_project_context.md`, `core/command.py`, `bin/user_commands.py`, `settings.local.json`, `initrd/ai_helper.py`,
    `lib/security.py`, `requirements.txt`, `README.md`, `tests/` (39 files + `tests/quantum/`), `Skills/Context File/` (3 design-context files).
- **Authoritative design sources (in priority/clarity order):** `Skills/Context File/umer_os_skills.json` (canonical agent-skill contract),
  `MainTask/prompt/*.md`, `MainTask/Raw Data/*.docx` master prompts. Where a source is aspirational (e.g. `README.md` Project Structure),
  the repo + `LICENSE`/`setup.py` win.
- **Decided inconsistencies (resolve the strays):** H7 → **GPL-3.0 canonical** (fix Apache-2.0 in `developer_guide.md`/master prompts AND `ai/providers.py`/`ai/resource_predictor.py` headers — H20);
  H11 → **Flutter (Dart) canonical** (decided 2026-08-20, overriding the earlier Kivy call). Backend = Python only; frontend = Flutter/Dart; "Flutter with java" was wrong (Java/Kotlin only for native Android platform channels). Drop `kivy` from `requirements.txt`; existing Kivy code/README is legacy drift to migrate.
  - **UI mandate (v1.5, 2026-08-20):** `ui/flutter_ui/` is the canonical Flutter/Dart frontend and MUST follow **HCI principles** (Nielsen's 10 heuristics) — see §4.8 of the standard. `ui/*.py` (Tkinter/CLI) is retired legacy. Frontend hotspots: H22 (Kivy in `setup.py`/`README.md`), H23 (`desktop_shell.dart` duplicated app registry → one `AppRegistry`), H24 (jargon labels → plain language), H25 (legacy `ui/*.py`), H26 (Flutter a11y: `Semantics` + broaden tests).
  - **`boot/` scope (v1.6, 2026-08-20):** `boot/` is a **`/boot` management toolkit** for a Linux-hosted boot env (FHS/GRUB/systemd-boot/EFI+SecureBoot/UKI/bzImage/cmdline/microcode/splash/kdump/initrd) — NOT the microkernel entry (`kernel/umer_kernel.py` is). High quality (type hints, docstrings, `_selftest()`) but 🔴 fail-open trust checks: H27 (`bootloader.py:verify_kernel` trusts missing kernel), H28 (`efi_system.py:is_binary_trusted` trusts DISABLED/SETUP_MODE, ignores `dbx`) — both same class as H17; 🟡→🔴 H29 (`init.py` auto-accepts "I AGREE" waiver non-interactively); 🟡 H30 (10 `boot/` files say Apache-2.0), H31 (only `bootloader.py` has a tier label), H32 (`uefi_stub.c` is a non-functional C placeholder), H33 (hash inconsistency vs mandated SHA3-512), H34 (`boot/` CLI skips `core/command` contract).
  - **`bin/` scope (v1.7, 2026-08-20):** `bin/` = ~44 FHS `/bin` + `/usr/*` **user-facing command modules** (≈19k LOC) — the shell-command surface, separate from `boot/` and `kernel/`. It is the **dominant H6 offender**: 🟡 H35 (27/44 use wrong `def execute(self, *args)` vs `execute(args=None)->int`), 🔴 H37 (`LoginCommand -f`/`-F` sets `skip_auth=True` → password auth bypass, `crypt.crypt` never reached), 🟡 H36 (`SuCommand` runs `[sh,"-c",command]` as another user; `_exec_shell` stub silently `return 0`), 🟡 H38 (`ChageCommand` defined twice: `usr_cmds.py:3045` + `usr_commands.py:1938`), 🟡 H39/H8 (broad `except`), 🟡 H40 (0/44 carry a tier label). GOOD: no Apache-2.0 headers, all `subprocess` arg-list + `timeout` (no `shell=True`), no `eval`/`os.system`/`pickle`/`yaml.load`.
  - **`build/` scope (v1.8, 2026-08-20):** `build/` is **PyInstaller output** for the `UmerOS-GUI` freeze. Of 16 files (~42MB) only 2 are authored: `build/UmerOS-GUI.spec` (PyInstaller spec) + `build/__init__.py` (0-byte marker); the rest (`*.toc`/`PYZ-00.pyz`/`UmerOS-GUI.pkg`/`base_library.zip`/`localpycs/*.pyc`/`warn-*.txt`/`xref-*.html`) are **generated → out of review scope per §0**. The `.spec` is the only reviewable surface and reveals: 🟡 H41 (build freezes `ui/umeros_gui.py` = the **retired Tkinter GUI**, H25 — ships the wrong frontend, not Flutter), 🟡→🔴 H42 (`codesign_identity=None` = unsigned distributable, breaks zero-trust signed-artifact mandate; `upx=True`), 🟡 H43 (hardcoded absolute Windows path), 🟡 H44 (empty `datas`/`hiddenimports` + `optimize=0` + no codified build — extends H16), 💭 H45 (spec lacks license/tier label). `warn-UmerOS-GUI.txt` is benign Windows posix-module noise.
  - **`cloud/` scope (v1.9, 2026-08-20):** `cloud/` = the **OTA (over-the-air) update subsystem** (3 files; `cloud/ota_updater/update_system.py` ~67 LOC, `UpdateManager`). It is the zero-trust **update path** and the headline finding is a **🔴 fail-open verification**: `verify_and_apply` (L48-60) returns `True` + applies even when `self.crypto is None` ("skipping signature check"), and when crypto is present it only `self.crypto.sign(payload)` (self-signs) + fakes "PASS" — never calls the real `CryptoEngine.verify` (`security/crypto_engine.py`/`quantum/crypto_pqc.py` have PQC verify but are unused). So **unsigned/unverified updates are applied** — same class as H17/H27/H28, breaks signed-`.umerpkg` mandate (§4.2). Also 🟡 H47 (module skips baseline: `print` not `logging`, no `from __future__`, no tier label → should be `[EXPERIMENTAL]`), 🟡 H48 (hardcoded `update_url="https://updates.umeros.dev/latest"`, no pinned source/key), 🟡 H49 (docstrings overstate security + no rollback/audit). No license headers (clean, like `bin/`).
  - **`compatibility/` scope (v1.10, 2026-08-20):** `compatibility/` = the **Universal Compatibility Layer** (4 files, ~645 LOC) — runs foreign-OS apps (Linux ELF, Windows .exe via Wine, Android APK via ADB) + syscall translator. **Best tier-label discipline so far**: `container_engine.py` uses `[EXPERIMENTAL]`/TODAY/FUTURE throughout (good counterexample to `bin/` 0/44). Subprocess launches arg-list, no `shell=True` (injection-safe). Findings: 🟡 H50 (`container_engine.py:30` `Licence: Apache 2.0`, H7/H30), 🔴 H51 (`ZeroTrustContainer.execute_binary` L12-23 calls `capabilities.check(...)` but only prints + still runs → **fail-open zero-trust gate**, same class as H17/H27/H28/H46; unused), 🟡 H52 (foreign ELF/`.exe`/APK launched **unsandboxed** — no namespace/quotas, full env inherited; must sandbox before `[TODAY]`), 🟡 H53 (`container.py`+`syscall_shim.py` skip baseline: `print` not logging, no `from __future__`, no label), 💭 H54 (two divergent container models — `ZeroTrustContainer` vs `ContainerEngine`/`ContainerInstance`).
  - **`core/` scope (v1.11, 2026-08-20):** `core/` = just 2 files — `core/command.py` (32 LOC, the **base `Command` class every `bin/` command inherits**) + `core/__init__.py` (1 line). **`core/command.py:30` is the ROOT CAUSE of H6/H35**: base `execute(self, *args: Any) -> Any` (returns `Any`) contradicts the adopted `execute(args=None) -> int`, so the 27/44 `bin/` modules using `def execute(self, *args)` merely inherit the wrong base signature. 🟡 H55 (fix base `execute` to `execute(args=None) -> int` to resolve H35 at source), 🟡 H56 (base `Command` declares `privileges: List[str]` field but **never enforces** it — zero-trust commands must gate execution on declared privileges via `CapabilityManager`, cf. H37/H4), 💭 H57 (no tier label → should be `[TODAY]`; no license header, clean like `bin/`). Tiny, foundational, low-risk otherwise.
  - **`dev/` scope (v1.12, 2026-08-20):** `dev/` = ~43 FHS `/dev` **virtual device-node filesystem** modules (≈6,800 LOC) — central `DeviceManager`/`DeviceNode`/`DeviceType` (`dev/core.py`) registry + ~40 pseudo-device/subsystem/command modules. **Cleanest folder security-wise**: no `eval`/`exec`/`subprocess`/`shell=True`/`pickle`/`ctypes` anywhere; licensing clean GPLv3 (zero Apache-2.0 strays, good counterexample to `boot/`). Findings: 💭 H58 (0/43 carry a tier label), 🟡 H59 (base `DeviceNode.mode` defaults to `0o666` world-writable; many nodes explicitly `0o666` — null/zero/full/tty/ptmx/shm/tun/fuse/i2c/misc; only memory devices use `0o640`), 🟡 H60 (`DeviceManager.sync_to_filesystem()` dev/core.py:211 materializes real device nodes via `os.mknod`/`os.mkfifo`/`os.symlink_to` with NO capability gate — same "privileged op / no gate" family as H27/H28/H46/H51; gate it + restrict default mode), 💭 H61 (singleton registry has no lock). `memory_devices.py` = model to copy (`STRICT_DEVMEM`, `/dev/kmem` disabled, access checks log warnings).
